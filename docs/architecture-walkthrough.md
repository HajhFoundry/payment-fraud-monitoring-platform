# Architecture Walkthrough - Payment Fraud Monitoring Platform

## 1. Business Problem

Financial institutions process large volumes of customer transactions every day.

Some transactions may be suspicious due to:

- High transaction amount
- Foreign country usage
- High-risk merchant category
- Rapid transaction velocity
- Declined transactions
- Login security issues
- OTP failures
- Impossible travel login patterns

The goal of this platform is to detect suspicious activity, generate fraud alerts, support fraud case investigation, and provide reporting dashboards for fraud analysts and technology teams.

5. Fraud Detection Flow

When a transaction is created:

POST /transactions/

the platform:

Validates account exists
Stores transaction
Retrieves customer information
Sends transaction to fraud rules engine
Evaluates fraud rules
Creates fraud alerts
Returns fraud alert count

Example:

{
  "amount": 7000,
  "country": "USA",
  "merchant_category": "Crypto"
}

Possible alerts:

HIGH_AMOUNT_TRANSACTION
COUNTRY_MISMATCH
HIGH_RISK_MERCHANT
LARGE_FOREIGN_TRANSACTION
HIGH_RISK_HIGH_AMOUNT_MERCHANT


6. Fraud Rules Implemented
Transaction Fraud Rules
Rule	Purpose
HIGH_AMOUNT_TRANSACTION	Detects transactions above threshold
COUNTRY_MISMATCH	Detects transaction country different from customer country
HIGH_RISK_MERCHANT	Detects high-risk merchant categories
DECLINED_TRANSACTION	Flags declined transactions
LARGE_FOREIGN_TRANSACTION	Flags large transactions outside customer country
HIGH_RISK_HIGH_AMOUNT_MERCHANT	Combines merchant risk and amount risk
HIGH_TRANSACTION_VELOCITY	Detects many transactions within short time window
Login / Security Fraud Rules
Rule	Purpose
MULTIPLE_OTP_FAILURES	Detects repeated OTP failures
IMPOSSIBLE_TRAVEL_LOGIN	Detects rapid logins from different countries
OTP_SUCCESS_ON_RISKY_LOGIN	Detects OTP success from unusual device/location
MULTIPLE_FAILED_LOGINS	Detects repeated failed login attempts

13. Key Design Decisions

Why FastAPI?

FastAPI was used because it provides:

REST API support
Automatic Swagger documentation
Pydantic validation
Clean backend architecture
Why SQLAlchemy?

SQLAlchemy was used to:

Model relational tables
Manage database sessions
Connect Python APIs to PostgreSQL
Avoid writing raw SQL inside API routes
Why Postman and Pytest?

Postman was used for manual and exploratory API validation.

Pytest was used for automated regression testing.

Together they show both QA/UAT and automation skills.

Why Streamlit?

Streamlit allowed quick creation of dashboards and analytics without building a full frontend framework.
